### 环境

| 组件 | 期望 | 缺了怎么办 |
| --- | --- | --- |
| Android SDK | `/opt/android-sdk`，platform **android-34**，build-tools **34.0.0** | 见下方补装命令 |
| JDK | 17 或 20（本机 Zulu 20） | `java -version` 确认 |
| Gradle | wrapper 8.7（腾讯镜像） | 不用管，`./gradlew` 自动下 |
| AGP | 8.2.2 | 不用管 |

**第一次构建慢**：依赖缓存约 700MB，新沙箱要重拉，5–15 分钟。**用 `run_in_background`，别用短超时等**。

两个反复踩到的沙箱坑：

1. `/opt/android-sdk` 整个不存在时：
   ```bash
   curl -sSL -o /tmp/cmdtools.zip https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip
   mkdir -p /opt/android-sdk/cmdline-tools && unzip -q /tmp/cmdtools.zip -d /opt/android-sdk/cmdline-tools
   mv /opt/android-sdk/cmdline-tools/cmdline-tools /opt/android-sdk/cmdline-tools/latest
   yes | /opt/android-sdk/cmdline-tools/latest/bin/sdkmanager --licenses
   /opt/android-sdk/cmdline-tools/latest/bin/sdkmanager "platform-tools" "platforms;android-34" "build-tools;34.0.0"
   ```
2. `/root/.gradle/init.gradle` 预置内容有语法错误（`url https://...` 缺 `=` 和引号、`mavelCentral()` 拼错），
   改好还会撞上项目的 `FAIL_ON_PROJECT_REPOS`。正确做法是**在 settings 层注入**：
   ```groovy
   settingsEvaluated { settings ->
       def repos = settings.dependencyResolutionManagement.repositories
       repos.clear()
       repos.maven { url "https://mirrors.tencent.com/nexus/repository/maven-public/" }
       repos.google()
       repos.mavenCentral()
   }
   ```

### 签名（不照做就打不出能装的包）

`app/build.gradle` 的 release 用的是 **debug keystore**（别名 `androiddebugkey` / 密码 `android`），
路径写死 `~/.android/debug.keystore`。交接包里带着这个文件，**必须原样放回去**：

```bash
keytool -list -keystore ~/.android/debug.keystore -storepass android -alias androiddebugkey
# 期望 SHA256: EC:6B:79:F8:BA:D7:51:38:96:4A:1B:3F:77:EF:89:06:B2:5C:66:97:E7:9C:4D:0A:E8:3F:73:14:C1:6A:77:12
```

不放回去，Gradle 会自动生成新的，签名不同 → APK **装不上**（手机上报「签名不一致」，只能卸载重装，设置全丢）。

### 发版清单（每版走一遍）

1. `app/build.gradle`：versionCode +1、versionName 按规则改
2. `Changelog.java` 顶部加 `Entry`，**code 必须等于 versionCode**（`ChangelogTest` 校验，对不上测试红）
3. 跑全量测试 + `assembleRelease`（缓存热了约 35 秒）
4. 复制 APK 到 `/workspace/打工人闹钟-vX.Y.Z.apk`
5. 同步 `打工人闹钟-使用说明.md`（**头部版本号最容易漏**）与 `更新日志.md`
6. 更新 `布局现状清单.md`（若动了布局）

## 4. 版本号规则（2026-10-22 14:15 与用户确认）

用户原话：「1.47.0 以及更高版本号后续还可以用的，不用一直局限在 1.46.x 里」——
**1.47.0 可以重用**（当时那个包没发出去，不算占用），之后正常往上排。

| 改动性质 | versionName | versionCode |
| --- | --- | --- |
| 删功能 / 改数据格式 / 重写 | 主版本 +1，其余归零 | +1 |
| 加功能 / 改交互 | 次版本 +1，修订归零 | +1 |
| 修 bug / 调文案 / 调布局 | 修订 +1 | +1 |

**versionCode 铁律**：每打一个包 +1，**永不复用、永不回退**。跳号允许且正确
（115 是 1.47.0 撤掉留下的空号，不要回收）。同一个 versionName 可以对应两个 versionCode，
但必须是「同名不同号」的覆盖版——是补丁，不是常态。

**历史教训**：1.46.2 / 1.46.3 / 1.46.4 三个版本全是首页布局调整，同一件事的三次尝试，
却各占一个次版本号。**同一件事分几次做完，只涨修订号。**

**下一版**：修 bug 走 **1.46.5 / 120**；功能或交互改动走 **1.47.0 / 120**。

## 8. 别再犯的坑

| 坑 | 教训 |
| --- | --- |
| 通知渠道改名只改字符串 | 名字建好就刻进系统库，**改代码无效**，只能换 ID 重建。`ChannelTest` 用 id→名字快照守门 |
| 拍脑袋估高度 | 「标题并卡」曾估省 188dp，实际每张卡要加 36dp 卡头，四张净省仅 44dp。**要算卡头，别只算内容** |
| 删了布局 id 还在测试里引用 `R.id.xxx` | 编译直接失败。改用 `getResources().getIdentifier(name, "id", pkg)` 断言返回 0 |
| 反射测试跟着界面迁移失效 | `showWeekBigDialog` 等从 `MainActivity` 搬到 `SettingsActivity`，反射目标要一起改 |
| 使用说明头部版本号漏改 | 改了三处日志忘了头部。**发版清单第 5 步专门点名** |
| 一个功能分三刀做 | 占掉三个版本号，看起来像三次功能升级。**动手前想清楚整件事的样子** |
| 文档重复记录同一信息 | 现状表写 v1.42.0、实际 1.46.4。**同一事实只在一处写**。v1.46.6 起文档已进 `docs/` 随仓库版本控制，改错能 `git diff` 看出来——但写错仍然没人替你发现 |
| 停止入口只靠权限 | 响铃页（后台拉起受限）、通知（权限可关）都可能没有，用户只能强行停止 App。**凡是「必须能停下来」的动作，要留一条不依赖权限的路径**——v1.47.1 的首页「正在响铃 · 停止」就是这条 |
| 界面外改状态不通知界面 | 通知栏按钮、桌面小组件改完 Prefs，界面不会自己刷新——刷新只在 `onResume`，而「退出去再进来」正好掩盖了它。Activity 之外改状态一律 `UiRefresh.request()` |
| 日志页一次性渲染全部条目 | 1.46.5 补录后 **114 条 ≈ 670 个 View**（旧记录估 570，低估了），进页面会卡。v1.46.6 已改分批（首帧 105），但**还没真机确认是否彻底不卡**——装上后留意一下 |
