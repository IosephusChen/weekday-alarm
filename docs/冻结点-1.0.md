# 冻结点：1.0 之后不能再改的名字

> 2026-10-27，v1.0.0 发布前整理。**这一页只回答一个问题：哪些字符串改了会让用户丢东西。**

## 为什么单独列一页

代码里的 API 改名有编译器兜底，配置项改名没有。下面这些名字都是**直接写进用户手机**的：

- SharedPreferences 的 key 改了 → 读不到旧值，等于那项设置回默认，用户看到的是「我的设置没了」；
- SharedPreferences 文件名改了 → 整份设置一起读不到，比单个 key 更彻底；
- 通知渠道 ID 改了 → 旧通知挂在旧渠道上，删不掉也改不了，用户得去系统设置里手动清。

这三种改动的共同点：**编译通过、单元测试全绿**（因为测试也用新名字），
只有装在真机上升级一次才会露出来。所以 `FrozenKeysTest` 把当前值逐个钉死，
改一次就要在测试里改一次——那一步就是最后的机会问自己「值得吗」。

## 四、通知渠道 ID（4 个）

| 常量 | ID | 用途 |
| --- | --- | --- |
| `App.CHANNEL_ALARM` | `alarm_channel_v3` | 闹钟响铃与全屏页（最高优先级） |
| `App.CHANNEL_SNOOZE` | `snooze_channel_v1` | 稍后提醒 |
| `App.CHANNEL_BEDTIME` | `bedtime_channel_v1` | 睡前提醒 |
| `App.CHANNEL_TEST` | `test_channel_v1` | 引导页「测试通知」、响铃时长到期等低优先级提示 |

渠道 ID 后面那个 `_v3` / `_v1` 是历史遗留：v0.1x 时改过三次闹钟渠道（音量、声音、
免打扰各自调过），每改一次就换个 ID，旧渠道留着不删。**1.0 之后不要再升版本号**——
换 ID 等于用户之前对「闹钟」这个渠道做过的静音、震动设置全部作废。

## 五、真要改的时候怎么做

不是「绝对不能改」，是改的时候要带迁移：

1. 读旧名字 → 写到新名字 → 删旧名字（`Prefs` 里已有先例：`KEY_ALARM_HOUR` 迁到
   `KEY_ALARMS`，靠 `KEY_ALARMS_MIGRATED` 标记只迁一次）；
2. 迁移代码要能在「全新安装」（旧名字不存在）和「老用户」两种情况下都正确；
3. 改完更新 `FrozenKeysTest` 里的冻结表，并在表上留一行注释说明为什么改。

## 六、顺带冻结的两件事

- **包名 `io.github.iosephuschen.weekdayalarm`**：改了就是另一个 App，老用户收不到更新。
- **签名证书**：`weekdayalarm-release.jks`，SHA-256 `D4:17:FB:1F:96:87:D7:EC:F5:F8:4F:A4:69:AE:94:8D:6A:7D:BA:FC:7C:12:B9:94:F8:B0:15:8C:45:BD:B1:26`。
  换了它，所有已装用户必须卸载重装（设置全丢）。keystore 与口令要备份两处。
  2026-10-27 已换过一次（第一代 `daxz-release.jks` 主体是 `CN=DaxiaoWeekAlarm`，与统一后的英文名对不上），
  换证记录见 `恢复说明.md` 第三节。**1.0 发出之后不再换**。
