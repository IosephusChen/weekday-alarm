### v0.80.1 做了什么（「下一个」补上主语 + 4×4 底部换下次闹钟）

用户看完 v0.80.0 的桌面截图，两条：「换成下次闹钟吧」；「4×2 的闹钟小部件的
『下一个 13:40 午休』这句话让人摸不着头脑，可以改成『下次闹钟 13:40 午休』」。

- **「下一个」是个没有宾语的量词**。`TodayCard.subText` 原来按「今天 / 以后」分两套说法：
  当天的写「下一个 13:40 午休」，以后的写「下次 明天 07:00 起床」。前者读起来像
  「下一个什么」——下一个闹钟？下一节课？下一件事？
- **两套说法合成一套**：新增 `TodayCard.nextTail()`，统一「下次闹钟 」+ `ringText`，
  时间关系（明天 / 后天 / 10月28日 周三）交给前缀。首页状态卡、4×2 部件、4×4 底部
  三处都走这一个函数，不会各自长歪。
- **4×4 底部第二段从假期倒计时换成下次闹钟**。v0.80.0 选倒计时的理由是「与首页同源、
  日历格子答不了」，但漏了数据边界：`HolidayCountdown.SCAN_DAYS = 120`，2026 年 10 月
  查下一个假已经是 2027 元旦，整段消失，底部常年只剩「19 天班 · 12 天休」。下次响铃
  天天都有，这一行才稳定是两段。
- **没有启用的闹钟时只留统计**，不写「下次闹钟 --:--」这种半句话。
- **测试**：644 条（+3）0 失败。`TodayCardTest.subText_prefixAndNextVsFuture` 换成
  `subText_alwaysNamesTheSubject` + 新增 `nextTail_isTheSameWordsAsSubTextTail`；
  `MonthWidgetTest.countdown_matchesHomeCard` 换成 `next_matchesHomeCard`（走新增的
  `compute(ctx, today, next)` 注入重载，`nextRing` 读真实时钟没法钉相对词）+
  `next_hiddenWhenNoAlarm`；`MonthWidgetLayoutTest` 新增
  `footer_worstCaseFitsWithoutEllipsis`——最长那句实测 515px / 可用 678px（172dp / 226dp，
  余 54dp），改成 `<= width/2` 反向验证过会红。

> **这版学到的一件事**：上一版（v0.80.0）我把「倒计时可能不出现」当成已知限制写进文档，
> 但没意识到它会让整行**常年**只有一半。用户看到的不是「有时少一段」，是「从来只有一段」。
> 选信息项时先问「它一年里有多少天是空的」，别只问「它有没有用」。

> **一个待确认点**：底部现在带闹钟标签（「…下次闹钟 明天 07:30 起床」）。标签长了
> （比如八个字）会触发 `ellipsize="end"` 砍尾。测试钉的是四字标签。真机上若被截，
> 可以考虑底部只写时刻不带标签。



### v0.80.0 做了什么（小组件去请假按钮 + 睡前提醒去 Toast）

用户两条反馈：「设置好睡前提醒后有个弹窗提示，我觉得没必要」；「4×4 的日历小部件上的
请假/加班按钮去掉吧，请假加班没必要做到小部件上，增加误触风险……去掉按钮后，4×4
小部件页面会有点空，你看看增加点什么信息上去」。

- **删 4×4 底部「今天 / 明天不上班」**。判断依据：桌面小组件是「看」的东西，不是「改」
  的东西——手指扫过就标错一天，改回来要进 App 找到那一天（还可能是过去的日子）。
  而请假这件事本身低频，进 App 点两下并不麻烦。v0.47.0 加、v0.48.0 补成一对、v0.77.4
  刚降过权，这次直接撤掉。
- **空出来的位置放一句话**：`22 天班 · 9 天休 · 距元旦还有 67 天`。
  选这两项的理由是「日历格子答不了的事」——数 42 格里有几天班很费劲，而倒计时与首页
  今天卡同源（`HolidayCountdown`），等于把首页那块信息顺到了桌面。
- **口径与格子一致**：`if (work ? !leave : overtime) workDays++;`——请了假就不算上班，
  休息日加了班就算上班，和格子上印的「假」「加」角标同一套判断，不会出现「格子看着
  上班、统计说休息」。
- **4×3 不加这一行**：200dp 高、42 格已排到极限（v0.77.3 刚修完压字），再挤一行会把
  字压回去。`withActions()` 因此改名 `withFooter()`，语义从「有没有按钮」变成
  「有没有那行字」。
- **睡前提醒去掉 Toast**：那一行右侧当场从「22:00」变「22:30」，再飘一条
  「已设置 22:30 的睡前提醒」是把同一句话说了两遍。关掉同理（行变成「关闭」）。
- **清干净整条链路**：`BedtimeReceiver` 的 `ACTION_TOGGLE_TOMORROW` / `ACTION_TOGGLE_DAY`
  / `EXTRA_DAY_OFFSET` 与 `toggleDay()`、`WeekWidgetRender.WeekModel` 四个 action 字段与
  `actionText()` / `isMarked()` / `bindAction()`、`bg_widget_action.xml` +
  `bg_widget_action_on.xml`、`WidgetLeaveTest` 整个文件（14 条）。`bg_hero_pill_on.xml`
  注释里「与 bg_widget_action_on 同一套视觉」同步改成「v0.80.0 起只剩首页一处」。
- **测试**：641 条（-10，删了 WidgetLeaveTest 的 14 条、加了 4 条）0 失败。
  `MonthWidgetTest` 新增 `stats_countsWholeMonth` / `stats_followsVacationMark` /
  `countdown_matchesHomeCard`；`MonthWidgetLayoutTest` 新增 `footer_isQuietText` /
  `footer_staysOnOneLine`；`WidgetRemoteViewsTest` 新增 `minimalWidget_hasNoFooter`，
  并把 `monthWidget_actionButtonsShowText` 换成 `monthWidget_footerShowsStatsAndCountdown`。

> **这版最大的一个坑：底部那行千万别做左右分栏。** 第一版是「左 stats + 右倒计时」两个
> TextView，渲染出来右边整片空白——2026-10-26 测 10 月，下一个假是 2027 元旦，超出
> `HolidayCountdown.SCAN_DAYS = 120` 的窗口，`visible=false`。右边一空，左边那截就孤零零
> 挂在角上，像没画完。改成一句 `footerText()` 拼起来，拿不到倒计时就自然变短。

> **待真机确认**：底部那行在真实日期下多数时候只有「22 天班 · 9 天休」——2027 年节假日
> 数据要等国务院公布 + 远程增量下发，`SCAN_DAYS` 之外也拿不到。如果用户希望常年都有
> 第二段信息，可换成不依赖节假日数据的项（「本月已过 26 天」/「下次闹钟 明天 07:30」）。



### v0.79.0 做了什么（「提醒」两行改成「值 + 箭头」）

v0.78.0 交付后的真机反馈：设置页「睡前提醒」那行「看过去只有一个开关」，
不知道点进去还能设置；而且「交互还是得改一下，挺奇怪的」。

- **病根是这一行在说谎**。设置页里用户靠右侧元素判断这一行能干什么：开关 = 只能开关
  （振动、渐响），`›` = 点进去还有东西（周休制度、节假日数据）。睡前提醒是混血：
  画着开关，点整行却弹设置窗。**不是用户没注意，是这行长得像 A、行为是 B。**
- **两行都改成导航行**：右侧「当前值 + `›`」——`21:30` / `提前 1 小时` / `关闭`。
  睡前提醒副标题只讲条件（`仅明天上班` / `每天提醒` / 关掉时退回功能说明），
  响铃前提醒副标题恒定为「响铃前先在通知栏提醒一次」。
- **「关掉」不再是开关**，而是对话框里和各个时刻并列的第一张卡。双入口消失，
  也就没有「开关关掉 / 卡片选关闭」两套规则。
- **响铃前提醒一并改**：原来整行点击是开关、只有副标题那一小块（约 60dp 宽）能改提前量，
  几乎没人发现。现在整行进对话框。
- **弹窗底部「取消」→「完成」**：原来那张取消取消不了任何东西——点任意一张卡都已即时
  存下并关窗。现在它只在「只切了开关、没点卡片」时用到，名副其实。
- **「响铃前提醒」弹窗也改成点即生效**：原来 `showGroupPick` 要按「确定」，同组两个弹窗
  挨着打开却是两套规则。它只有一组选项，不需要二次确认，改用 `showPick`。
- **「其他时间…」不再先关弹窗**：滚轮叠在上面，取消就退回原弹窗接着选。
  原来 `dismiss()` 之后再弹滚轮，滚轮上按返回回到设置页、弹窗没了、什么都没改，像误触。
- **删两处死代码**：`PrefDialogs.preNoticeSummary`（副标题不再带提前量）、
  `PrefDialogs.setPreNoticeEnabled`（开关没了，「关掉再打开恢复上次值」无从触发）。
  `Prefs.getPreNoticeLastMinutes` 保留——`setPreNoticeMinutes` 仍在顺带维护那个键，
  删了会让老备份里这个键变孤儿。
- **测试**：651 条（+2）0 失败。`SettingsLayoutTest.bedtimeSwitch_togglesAndRestoresLastTime`
  换成 `bedtimeRow_showsTimeInsteadOfSwitch`；`PreNoticeTest.switchOff_thenOn_restoresPreviousMinutes`
  换成 `rowValue_followsMinutes`、`preNoticeDialog_hasOneHourOption` 去掉「按确定」那一步
  并改断言「点完就关窗」；`BedtimeDialogTest` 新增两条（底部只有「完成」、
  点「其他时间」不关主弹窗）。

> **这版的一个坑**：`AlertDialog.getButton(BUTTON_NEGATIVE)` 永远不返回 null——
> appcompat 会把三个按钮都 inflate 出来，没设文案的那个只是 `GONE`。
> 判「有没有取消」要看 `getVisibility()`，不是看 null。

> **另一处需要真机确认**：睡前提醒的开关没了，关掉要「点行 → 点关闭卡」两步。
> 如果用户觉得麻烦，可以加回一个「长按行快速开关」，但不建议——那等于把双入口又装回去。

### v0.77.4 做了什么（本月班表部件：底部两个按钮降权）

用户问「底部两个按钮有什么想法」。先真渲染了四种状态对比，再定方案。

- **诊断**：抢戏的根源是**面积**不是深浅。两个按钮各约 350×50px，是整个组件里唯一的连续色块——
  日历是零散短线、标题是线、底部是面，面永远比线重。另有三处加剧：圆角三档（卡片 22dp /
  徽章 999dp / 按钮 10dp）、按钮 10sp **bold** 比日历数字（10sp 常规）还重、满宽 + 4dp 缝
  正好是标签栏（tab bar）的形态，而 tab bar 的语义是「切视图」不是「执行动作」。
- **改法**：`widget_month_actions` 两侧各让出 34dp、高度 20→18dp；`bg_widget_action` 底色
  `#33FFFFFF` → `#1FFFFFFF`、圆角 10dp → 999dp；两个 off 态 TextView 去 bold、
  字色 `#FFFFFF` → `#E6E4FF`（与「闹钟已开启」同灰阶）。宽度合计从约占 99% 降到约 71%。
- **「已请假」态不动**：保留 `#F5F4FF` 实白底。它是例外状态，跳一下提醒「你今天标了假」是好事。
  只把圆角跟着改全圆，否则切换瞬间会露出「一个圆一个方」。
- **测试**：641 条（+3）0 失败。三条分别是：按钮合计宽度 < 容器 78%、幽灵 pill 四处属性
  （18dp 高 / `#E6E4FF` 字 / 非 bold / 12% 白底 / 圆角 ≥ 半高）、两个状态共用同一档圆角。

> **这版发现的一件事：圆角那项改动其实没有视觉效果。** 按钮降到 18dp 高之后，10dp 圆角
> （30px）已经超过半高（27px），渲染时被 clamp 成半圆，和 999dp（2997px）看起来完全一样。
> 反向验证时撤掉它测试不转红，才查出来。保留 999dp 的理由是声明意图：以后有人把按钮加高到
> 26dp 做图标，10dp 会退化成圆角矩形，999dp 自动还是 pill。**教训：改「尺寸 + 圆角」这类
> 组合属性时，先算一下 clamp 关系，别把等价改动当成视觉改进写进汇报。**



### v0.77.3 做了什么（本月班表部件：标题行分层 + 修两个变体的压字）

用户提「日历小部件参考闹钟小部件再美化一下」。做的时候挖出两个一直没被发现的压字 bug，
所以这一版是「美化 + 修 bug」各一半。

- **标题行分层**：`widget_month_sub`（「大周 · 休2天」）加 `bg_chip_white` 圆角徽章 +
  6dp/1dp padding、白字；`widget_month_alarm` 颜色 `#E6E4FF` → `#C9C4FF`、marginStart 8 → 12dp。
  原来两者都是 10sp 裸文字同色、只隔 6dp，读起来像一句话。
- **修：4×3 的「班 / 休」下半截一直被裁**（v0.69.0 起就存在）。200dp 合同高度下每格只有
  18dp，两行文字要 30dp。修法四件：`includeFontPadding=false`、字号 9.5sp/8sp、
  padding 10→8dp、表头 marginTop 6→4dp。另外 `widget_month_actions` 默认 `visibility="gone"`
  ——这个变体本来就没有按钮，布局写 `visible` 会让测量时白占 20dp。
- **修：4×4 也压字**，只压 2dp、肉眼看不出来。同一个修法，另给标记行加 1dp 上边距找回成组感。
- **今天的高亮块四边内缩 1.5dp**：42 格之间只有 2dp 行距，整格色块会糊成一片。
- **测试**：638 条（+4）0 失败。`MonthWidgetLayoutTest` 四条：两个变体按合同高度渲染后
  逐格比对「View 高 vs `getLayout().getHeight()`」、标题行 chip 与降色、高亮块 margin。
  反向验证四条各自精确转红。

> **这次最值钱的教训**：「文字有没有被裁」不能用「bottom 有没有超出容器」判断。
> 垂直 LinearLayout 拿「父高减已用高度」作第二个子 View 的 AT_MOST 约束，空间不够时
> 直接把 TextView 的 measured height 压小——View 的 bottom 恰好等于容器高，断言恒成立，
> 但文字已经溢出 View 边界被父裁掉。正确判据是 `getHeight() >= getLayout().getHeight()`。
> 同理，凡是「测量结果」类的断言，先断言测量真的发生了（高度 > 0），否则测试会空转。



### v0.77.2 做了什么（修跨零点后小组件仍显示昨天）

用户 00:07 截图：已经是周一，4×2 组件还写着「今天休息 / 周日」，七格高亮也在周日。

- **根因**：三个组件的内容（今天状态、七格高亮、整月卡的今天格子、「下次 明天」措辞）
  都是渲染时按 `LocalDate.now()` 算，但系统 `updatePeriodMillis` 最小 30 分钟——
  零点那一刻没人叫它重画，最多带昨天的状态显示半小时。
- **修法**：新增 `WidgetTicker`（每天 00:00:30 挂精确闹钟）+ `WidgetTickReceiver`
  （收到就 `Widgets.updateAll`）。挂载点放在 `Widgets.updateAll` 末尾，
  开 App / 开机 / 改设置 / 导入 / 闹钟变化都会重新武装；接收器触发后
  `updateAll` 又会把下一天挂上，自维持。
- 用 `setExactAndAllowWhileIdle`（同提前提醒），无精确权限退回 `setWindow(60s)`。
  没用 `ACTION_DATE_CHANGED`：受保护广播，静态注册收不到。

### v0.56.0 · 年度闹钟撤掉 —— 已发版（2026-10-22，versionCode 110）

**A8 与 A9 一并取消。** v0.57.0 做过公历年度闹钟，用户试用后判断「这个功能是多余的」，
要求舍弃、回到 v0.55.4 的基线上继续迭代。测试 463 → **444**（`YearlyAlarmTest` 19 条随之删除）。

**为什么砍**（结论要留在文档里，否则下个会话会当成待办重新捡起来）：

- **需求错位**。生日、纪念日真正要的是「提前几天提醒买礼物」，不是「当天早上响一遍」——
  被叫醒时礼物已经来不及买了，而且人本来就要起床。
- **四处特判**。`ignoresVacation()` 请假豁免、`scanDays()` 窗口 90→367 天、`nextRing()` 整体放宽、
  备份多两个字段 + 残缺数据禁用分支。这四处都是「只有三种模式就不存在」的代码，是 bug 温床。
  其中 `nextRing()` 那处是**全局**的：为一个边缘模式，把每次算下次响铃的循环都拉长了。
- **农历版更不值**。`LunarCalendar` 要补反向换算、闰月得让用户选闰哪个月、除夕是腊月最后一天，
  2–3 天成本换「长辈农历生日」一个场景，而系统日历的农历提醒做得更好。

**怎么砍的**：

- `git reset --hard 3817181`（v0.55.4 的提交），工作区无残留；`grep -r YEARLY|MonthDayWheel|scanDays` 零命中
- 原提交打了 tag `archive/v0.57.0-dropped`（指向 `1e299c0`），万一改主意能一键找回，不用重写
- **versionCode 跳号不退回**：当时用 116 而不是退回 114——115 那个包已经打进过手机，
  Android 不允许降级安装，退回 114 会直接装不上。跳号是这里唯一正确的选择
  （三个都是重排前的旧号；重排后这一跳被抹平，v0.56.0 = 110、v0.55.4 = 109，编号连续）
- 更新日志加了 v0.56.0 条目，把「试过又拿掉」和跳号原因都写进去，
  免得以后看到跳号以为是漏了（重排后跳号已不存在，这条留作规则依据）

**如果未来真要捡回来**：方向不是「更准的日期算法」，而是「提前 N 天提醒」——
那需要一个倒数日/待办模块，已经超出闹钟 App 的定位，别硬塞进 `Mode`。

### v0.55.1 · 去掉横幅背景模糊 —— 已发版（2026-10-22，versionCode 106）

**v0.55.0 的回归。** commit `b24c71f`，测试 420 → 421。

v0.55.0 按 `isCrossWindowBlurEnabled()` 挂了 `FLAG_BLUR_BEHIND` + `setBlurBehindRadius(20dp)`，
在小米 HyperOS 上实际效果是**整屏磨砂**——除横幅外，屏幕上所有内容都糊成一片。
用户原话：「这个不应该的，我们做悬浮通知的初衷就是为了不让屏幕上的其他内容被闹钟全部挡住」。

**这个标志彻底删掉了，不要再加。** `FLAG_BLUR_BEHIND` 语义上是「模糊窗口背后的背景」，
但模糊区域由 WMS 按窗口算，各家 ROM 实现不一致，第三方悬浮窗拿不到「只糊自己那一块」的保证。
透明感只用 alpha（88% 不透明深色卡）做。

守门测试是 `FloatingAlarmTest.source_neverTouchesBlurBehind`——**读源码**，
代码行出现 `FLAG_BLUR_BEHIND` 或 `setBlurBehindRadius` 就红。为什么不用 LayoutParams 断言：
Robolectric 的 `ShadowWindowManagerImpl` 没有跨窗口模糊开关，`isCrossWindowBlurEnabled()` 恒 false，
「系统支持时会不会挂」这个分支在单测里永远走不到——只断言 flags 的话，
有人把 `applyBlurIfSupported` 原样加回来测试照样绿。已变异验证（加回一行 → 两条立刻红）。

### v0.54.0 · 小窗不是整屏 + 时间不再说谎 + 卡片回单行 —— 已发版（2026-10-22，versionCode 102）

| --- | --- | --- |

**悬浮窗为什么不用 Activity**：Activity 就算做成 dialog 主题，窗口仍然占满整屏、会盖状态栏，

图标 34 + 10 间距，两个药丸约 158（「停止」46 + 「5 分钟后再响」98 + 间距 14），

`NotifCardTest` 新增三条把这件事钉住：按钮必须是 32dp 固定高 + `Gravity.CENTER`、

**第二条**：RemoteViews 里的颜色只能自己读 `uiMode`（`NotifCard` 已经这么做了），
但 **drawable 里的颜色必须走资源**——写死一个浅色，深色模式下就是白字压白底。
`NightModeTest` 用 `@Config(qualifiers = "night")` 直接比亮度，防止再犯。

**第三条（行为反转）**：v0.31.1 定过一条规则「解锁使用中只发通知，别打断手里的事」，
当时三条路径都按它走。v0.53.2 把**正式响铃**改成无条件弹窗——闹钟本来就该打断人，

`ScreenLock.shouldPopup` 因此只服务提前提醒了，改它之前先看清调用方。

**第四条（App 改不了的）**：锁屏上盖一层界面需要 ROM 的「锁屏显示」权限（荣耀/华为/OPPO/vivo 都有）。
它不在 Android 权限体系里：`Settings.canDrawOverlays` 读不到、`ACTION_MANAGE_OVERLAY_PERMISSION`

### v0.53.0 · 通知栏：时间不再说谎 + 品牌紫 —— 已发版（2026-10-21，versionCode 99）

用户提了两件事：**「提示的响铃时间是静态的，不会随时间变化」**、
**「UI 好看但没特色，容易和系统闹钟混淆，加点紫色」**。

**一、相对时间在通知里天然是错的**

原文案 `1 小时后 · 14:10 响铃`。通知发出去就不再更新，而它要在栏里躺满整个提前量
（5 分钟到 2 小时不等）。躺到只剩 10 分钟时，那句「1 小时后」已经错了 50 分钟。

真正会动的只有两种做法：

| 做法 | 代价 | 结论 |
| --- | --- | --- |
| 自己起服务 / AlarmManager 定时重发通知 | 每分钟唤醒一次 CPU，国产 ROM 还会掐后台 | 不做 |
| `setUsesChronometer(true)` + `setChronometerCountDown(true)` | 零成本，SystemUI 自己每秒刷 | **采用** |

所以：正文写**绝对时间**（`14:10 响铃` / `明天 14:10 响铃`），头部挂**系统倒计时**。
一个说「什么时候」，一个说「还剩多久」，互不重复。

横幅（heads-up）保留相对时间 `1 小时后 · 14:10`：它只出现几秒，不存在失真，
而且「还有 10 分钟」比「14:10」更催人。锁屏和通知栏用的是折叠卡片，那边只写绝对时间。

**二、品牌色从哪来**

原来图标底是 8% 黑的灰圆、按钮是 12% 黑的灰药丸——和系统通知长得一样，
再加上系统按壁纸取色，整条通知没有一处属于本应用。

现在直接复用首页 hero 的渐变（`indigo #4F46E5` → `violet #7C3AED`，135°）：

| 元素 | 之前 | 现在 |
| --- | --- | --- |
| 图标底 | `#14000000` 灰圆 | 紫渐变圆 + 白图标 |
| 「关闭闹钟」 | `#1F000000` 灰药丸 + 黑字 | 紫渐变药丸 + 白字 |
| 通知强调色 | 未设（系统灰） | `setColor(indigo)`，头部应用名跟着紫 |
| 睡前提醒 | 未设 | 同样 `setColor(indigo)` |

深色模式不再需要单独的 drawable：紫底白字/白图标在深色卡片上同样成立，
`bg_notif_icon_dark` / `bg_notif_action_dark` 已删。

**踩到的坑**：`Notification.getColor()` 不是公开 API，测试里要用 `n.color` 字段。

**测试**：383 个，0 失败。新增 6 条：正文不含「小时后 / 分钟后」、开了 chronometer 且方向是倒计时、
`when` 是未来时刻、强调色是品牌紫、`whenText` 四种日期措辞、`triggerAt` 解析与脏数据兜底。

### v0.52.0 · 过去的日子也能补记 —— 已发版（2026-10-21，versionCode 95）

v0.51.0 把过去设成只读，用户的下一句是「我需要过去的日子也能够标记」。
理由很直接：请假常常是事后才想起来记的，只读等于把最常见的补记场景堵死。

**设计：菜单只有一套，过去与未来只差措辞**

| 位置 | 过去（d < today） | 今天及以后 |
| --- | --- | --- |
| 菜单项 | 与未来完全相同（上班日：请假 / 加班；休息日：加班） | 同左 |
| 标题 | `10月15日 周三 · 上班日 · 已过去` | `10月16日 周四 · 上班日` |
| 新增 Toast | 「已补记请假（那天已过去，不影响闹钟）」 | 「已标记请假，当天闹钟跳过」 |
| 数据 | 同一个 `vacation_dates` / `overtime_dates` 集合 | 同左 |

过去标记不参与排程：`ScheduleManager` 从今天往后逐日算，`d < today` 根本不会进循环。
所以补记 / 删除过去标记都不会让任何闹钟多响或少响。

**统计与清除回到「全部」**（v0.51.0 的收窄被撤销）：

| 项 | v0.51.0 | v0.52.0 |
| --- | --- | --- |
| 统计 | 只算 `d >= today` | 算全部（`dates.size()`） |
| 清除 | 只清 `d >= today` | 清全部（`clearMarks`） |

正是 v0.50.1 修掉的矛盾。既然过去也能标，标记就只是一条事实，没有时效之分。
想只删某一天，在日历里点那一天取消（`removeMark` 仍在）。

| 改动 | 落地方式 |
| --- | --- |
| 去掉过去拦截 | `CalendarPanel.onDayClick` 删除 `if (past) { ... return; }` 整段，菜单统一构建 |
| 措辞分流 | `toggleVacation` / `toggleOvertime` 增加 `boolean past` 参数，只影响 Toast；标题由 `past` 追加「· 已过去」 |
| 统计 | `countUpcoming` → `countMarks`，直接返回集合大小 |
| 清除 | `Prefs.clearUpcomingMarks` → `clearMarks`，清空整个集合；对话框标题「清除全部…」并说明过去记录也会删 |
| 文档 | `HelpActivity` 两条、`打工人闹钟-使用说明.md` 功能段 + 请假步骤 + 新增 v0.52.0 日志 |

**测试**：382 个，0 失败。`PastMarkTest` 17 条，过去部分从「拒绝 / 只删」改为：
过去上班日给两项 / 过去能补记请假且 Toast 含「补记」不含「跳过」/ 过去休息日能补记加班 /
补记后显示「取消请假」并能删 / 过去同日双标记渲染「假加」；统计算全部 / 清除清全部且数字一致 /
