## 一、轮班备份只写不读：切回轮班时原表被 4 天默认表顶掉（高）

**已证实。** 验证命令与结果见本节末。

- **复现**：排过「上 12 休 2」这类轮班表 → 「我的班表」点「双休」 → 保存 → 再点「轮班制」
  → 保存。原表的周期、起始日、每天上哪个班**全部消失**，变成「4 天、每天都是第一个班次」，
  起始日变成今天。此后闹钟按 4 天循环响，等于每天响。
- **根因**：`Prefs.getRotationBackup()` 在 `app/src/main` 里**只剩定义**（`Prefs.java:399`），
  全仓库唯一调用点是测试 `DayPlanPrefsTest.java:321`；而 `ScheduleDraft.java:208` 仍在调
  `Prefs.saveRotationBackup()`。**备份成了只写不读的死数据。**
  生产侧入口 `PlanCardsView.startRotation()` 只判断 `draft.shiftCycle`，为空就直接铺 4 天默认表。
  这个「读备份」的调用点当年随 `ShiftCycleSheet.show()` 一起被删了（v1.20.1 清死代码那次）。
- **验证**：`grep -rn "getRotationBackup" app/src --include="*.java"`
  → `main` 里 0 个调用点，`test` 里 1 个。
- **候选方向**（未批准）：只在 `PlanCardsView.startRotation()` 里补——`shiftCycle == null` 时
  先读 `Prefs.getRotationBackup(act)`，有就 `draft.setRotation(...)`，没有才铺默认表。
  不改备份格式、不动 `commit()` 的写入时机。
- **代价提醒**：用户排一张「上 12 休 2」要几十次点击，切去看一眼双休就没了。这是三条里最该先修的。

## 二、导入旧配置后第 1 页绑的还是旧草稿（高）

**未验证。** 这条要读 `PlanCardsView` 的字段与 `GuideActivity.onImportedFromBackup()` 才能确认，
本次没展开。

- **复现**：全新安装 → 引导页点「导入旧配置」，导入一份「单休 / 轮班」备份 → 跳到权限页
  → 点「上一步」回第 1 页 → 卡片仍显示导入前的「双休」 → 点「单休」修正 → 走完引导点「开始使用」。
- **实际**：界面接受了这次点击，但 `complete()` 提交的是导入后重新 `load()` 的新草稿，
  用户刚选的「单休」被静默丢弃；第 1 页显示的选中卡与将要生效的班表也不一致。
- **根因（Trae 说法，待核）**：`onImportedFromBackup` 里 `draft = ScheduleDraft.load(this)`
  换掉了字段，但 `PlanCardsView` 构造时把旧草稿存成了 `final` 字段，`planCards.reload()`
  读的仍是旧对象。v1.12 之前这里调 `reloadWeek()` 每次现读字段，v1.18 抽共享组件时
  把「现读」变成了「构造时捕获」。
- **候选方向**（未批准）：`PlanCardsView.draft` 去掉 `final`，加包级 `bindDraft(ScheduleDraft)`；
  `GuideActivity` 里 `planCards.reload()` 换成 `planCards.bindDraft(draft)`。
  **不要重建 `PlanCardsView`**——重建会把 `addDayBoxes()` 的七个子控件再插一遍。

## 三、草稿未落盘时删班次，被删的 id 会跟着 `commit()` 写回去（中）

**部分证实**：`dropMissingShifts` 确实已不存在（全源码 0 处），调用链未逐行验证。

- **复现**：引导页（或未保存的「我的班表」）正展开一张轮班表 → 点「管理班次」→ 长按删除
  一个班次 → 点「完成」关闭 → 走完引导 / 保存班表。
- **实际**：`ShiftBookDialog.confirmDelete` 已把 Prefs 里 `shift_cycle` 对应位置改成 -1，
  但草稿里的旧 id 还在，随后 `commit()` 把旧数组原样写回。那天的 `mask` 仍是「上班」，
  而 `shiftOn()` 找不到班次返回 null——**日历说上班、闹钟却没有时刻**，
  跟着全局班表且不限班次的闹钟那天仍会响。
- **根因**：`b203159` 删掉了 `WeekScheduleActivity.dropMissingShifts()`，而新入口
  `PlanCardsView.tvPlanShiftHint` 的回调只做 `renderRotation()`，没做同样的清理。
- **验证**：`grep -rn "dropMissingShifts" app/src --include="*.java"` → 0 处。
- **候选方向**（未批准）：把清理逻辑搬进 `PlanCardsView`，班次弹窗「完成」回调里先清后画
  （`shiftCycle` 里查不到的 id 置 -1、同步 `cycleMask`、`dirty = true`）。
