> 量于 2026-10-22 13:30，基线 v0.56.0（versionCode 116）。
> **13:36 第一刀落地（v0.56.1）：首页 1578 → 1388dp。**
> **13:52 第二刀落地（v0.56.2）：1388 → 1191dp，日历进第一屏。**
> **14:10 第三刀落地（v0.56.3）：1191 → 1105dp，闹钟上移、总开关删除。** 详见文末「已改动记录」。
> 方法：读布局 XML + `themes.xml` 样式 + 动态生成代码（`AlarmRowRenderer` / `CalendarPanel`），
> 按 dp 逐项累加。**不是真机测量**，误差约 ±5%，量级可信、个位数不可信。

### 关键发现

**第一屏只能看到闹钟卡的一半，日历完全看不见。**

按 700dp 切分：

- 0–514dp：标题 + 今日卡 + 排班区（第一屏的上半部分）
- 514–700dp：闹钟标题 + 闹钟卡的开关行 + 1 条闹钟（第一屏结束）
- 700–950dp：剩下 2 条闹钟 + 添加按钮（第二屏）
- **950–1388dp：日历（第二屏中段到第三屏）**

也就是说，想核对日历，必须先滚过整个闹钟列表。而日历是「核对班表、临时标请假」的入口——
v0.48.1 把它从独立页搬回首页的理由正是「多一次跳转就多一次放弃」，现在它变成了
「多滚一屏才能看见」，问题换了个形式还在。

### 空列表时

闹钟卡变成 232dp（空态 90dp 替代 3 行 × 66），合计 **1468dp ≈ 2.1 屏**。
也就是说，哪怕一个闹钟都没建，首页仍然超过两屏。

## 三、设置页（v0.60.0 分成三页，v0.82.0 分组重排）

参考澎湃系统闹钟的分层，主页只放高频项，其余进二级页。高度是 v0.60.0 的实测值
（354×786dp）；v0.82.0 只挪了一行、改了两处组名和两处合并，**没有重量**——
量级不变，下面标注的是按行数推算的增量，不是实测。

| 页面 | 内容 | 高度 |
| --- | --- | --- |
| 设置（主页） | 9 项 + 4 个组标题 | **约 1041dp ≈ 1.6 屏**（原 987dp，+54dp 一行） |
| 更多响铃设置 | 4 项 | 约 559dp（一屏内，少了一行稍后提醒） |
| 更多设置 | 10 项 + 3 个组标题 | 约 1294dp（并掉一个组标题与一张卡） |

主页 9 项（v0.82.0）：音量（就地滑块）、铃声、更多响铃设置 ›、周休制度、节假日数据、
睡前提醒、响铃前提醒、**稍后提醒**、更多设置 ›。

四个组名（v0.82.1 定稿）：**响铃 / 排班与节假日 / 提醒 / 更多**。
只改了两处口径——「闹钟」→「响铃」（这一组装的是响的时候什么样）、「其他」→「更多」
（只有一项，等于没分类）；另外两组试过问句式（上班日怎么算 / 什么时候提醒），
用户判定太口语化，已改回名词。
三个提醒（睡前 → 响前 → 响后）按发生顺序连排，因为改「响了之后多久再响」的人
不该先想到「它其实在下一层」。

二级页三组（`sec_all` 那段）：**排班与显示**（一周开始日 / 闹钟排到多远 / 日历显示内容）、
**帮助与关于**（运行状态 / 引导 / 说明 / 日志）、**数据与桌面**（添加到桌面 / 导出 / 导入，
由原「桌面小组件」+「备份与恢复」合并）。

**为什么不是一屏**：睡前提醒和响铃前提醒各带一行副标题（时间 / 提前量），
节假日数据也带说明，这几行 64–104dp；再加上 4 个组标题（47dp + 10dp 间距）。
压到一屏只能删掉这些状态信息，而那正是「不展开也知道现在是什么配置」的价值。
987dp 已经比 v0.59.0 的 2543dp 少了一多半，且高频项不需要点开。

**实现要点**（v0.60.0）：
- `MoreSettingsActivity extends SettingsActivity`，只覆盖 `layoutRes()` 换布局；
  绑定、刷新、所有对话框共用父类一份，没有复制代码。
- 父类的 `findViewById(...).setOnClickListener(...)` 全部改走 `bind(id, listener)`，
  控件不在当前布局里就跳过；`refreshAll()` 里同样按字段判空。
- `activity_more_settings.xml` 用 `sec_ring` / `sec_all` 两段，按 intent extra 显示其一。
- 音量滑块拖动中只改文字，松手才写 Prefs——每格都落盘会反复触发重排。

## 六、可动的地方（只列，不决策）

按「省多少 dp」排序：

| 做法 | 省 | 风险 |
| --- | --- | --- |
| 底部三块收进设置页，首页只留一个「设置与说明」入口 | 190 → 70，省 120 | 测试响铃多一步；但它本来就是低频 |
| 4 个 `SectionTitle` 并进卡片内部（当卡头） | 省 188 | 卡片视觉要重做，属于 A11 范围 |
| 日历默认折叠，点标题展开（记住状态） | 省 ~390（折叠态） | v0.44.0 独立成页被否，但折叠卡不同——它就在原地 |
| 倒计时并到状态行右侧 | 省 51 | 数字每秒跳，右侧空间够不够要看长文案 |
| 设置页分组默认折叠 | 省 400+ | 多一次点击才能看到项 |

前两条加起来能省 **308dp**，首页从 2.25 屏降到 **1.8 屏**；再加日历折叠能到 **1.2 屏**。

## 七、真机复核方法

静态估算不能替代实测。真机上复核任意模块高度：

1. 开发者选项 → 「显示布局边界」，看模块外框
2. 或截图后用像素量：`高度px ÷ 3.05 = dp`
3. 最准的是 Layout Inspector（Android Studio），直接显示每个 View 的 measuredHeight

如果实测与本文差超过 10%，以实测为准，并回写这份清单。

**为什么总开关该删**（不是「可以删」）：

1. **它是冗余的**：每条闹钟行右侧本来就有独立开关，系统自带闹钟也没有全局总开关。
   打工人通常只有 1~3 条闹钟，「全部停掉」逐条拨两下就到了。
2. **它是静默失败的源头**：关掉后一切照常显示，就是不响。为此要在五处补话——
   今日卡副标题、倒计时留空、桌面小组件「尚未开启」、睡前提醒「总开关还没打开」、
   编辑弹窗「先打开才会响」。一个功能需要五处解释自己，本身就说明它不该存在。
3. **它占的是第一屏最贵的位置**：86dp，正好是日历月份行 + 星期头的高度。

删掉后 `Prefs.isEnabled/setEnabled/KEY_ENABLED` 一并消失，67 处引用清到 0。

删 / 关到最后一条启用闹钟时调用 `cancelAllIncludingTransient`，语义从「关开关」变成「没有闹钟了」。
