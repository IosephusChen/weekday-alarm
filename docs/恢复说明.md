## 一、怎么恢复（四步）

**第 1 步：解压灾备包，从 bundle 建仓库**

```bash
cd /workspace
unzip -q 打工人闹钟-灾备包-20261022.zip      # 得到 备份-20261022/
git clone 备份-20261022/DaxiaoWeekAlarm-v1.46.6.bundle DaxiaoWeekAlarm
cp 备份-20261022/debug.keystore /workspace/debug.keystore
```

bundle 是单个文件的只读仓库，clone 出来就是完整历史（含 `docs/` 全部文档）。
校验：

```bash
cd /workspace/DaxiaoWeekAlarm
git rev-list --count HEAD     # 与灾备包 恢复步骤.md 记的数字一致即可
git ls-files | wc -l          # 应输出 204
ls docs/                      # 应看到全部文档：9 份 md + 线框（数量会随版本增加，别背数字）
git status                    # 应干净
```

> 提交数故意不写在这里：本文件本身就在仓库里，写死一个数，下次提交就过期。
> 具体数字由灾备包里的 `恢复步骤.md` 记录（它在仓库外，生成时校验）。

恢复后的布局：

```
/workspace/
├── DaxiaoWeekAlarm/              ← 代码仓库（含 .git 完整历史）
│   └── docs/                     ← 全部文档，随仓库版本控制（v1.46.6 起）
│       ├── 交接-给下一个会话.md    ← 开工必读，第一份看这个
│       ├── 历史-版本记录.md
│       ├── 更新日志.md
│       ├── 流程规范.md
│       ├── 布局现状清单.md
│       ├── 优化与新功能建议.md
│       ├── 打工人闹钟-使用说明.md
│       ├── 提示词-旧会话导出.md
│       ├── 恢复说明.md            ← 就是本文件
│       └── 预览-*.html / .png      ← 线框留档
├── debug.keystore                ← 签名密钥（覆盖安装靠它，别丢）
└── 打工人闹钟-vX.Y.Z.apk          ← 安装包
```

路径引用一律写成 `/workspace/DaxiaoWeekAlarm/docs/xxx.md`。
文档进了仓库之后，改错可以 `git diff` / `git checkout` 回滚——v1.46.6 之前它们散在 `/workspace` 根、
没有任何版本历史，这也是它们反复失真的原因。

**第 2 步：补 `local.properties` 并检查环境**

```bash
cd /workspace/DaxiaoWeekAlarm
echo "sdk.dir=/opt/android-sdk" > local.properties   # 这个文件不进仓库，必须自己建

java -version                                        # 需要 17 或以上（原环境 20）
ls /opt/android-sdk/platforms                        # 应有 android-34
ls /opt/android-sdk/build-tools                      # 应有 34.0.0
```

缺 SDK 的话装命令行工具：

```bash
curl -sSL -o /tmp/cmdtools.zip https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip
mkdir -p /opt/android-sdk/cmdline-tools
unzip -q /tmp/cmdtools.zip -d /opt/android-sdk/cmdline-tools
mv /opt/android-sdk/cmdline-tools/cmdline-tools /opt/android-sdk/cmdline-tools/latest
yes | /opt/android-sdk/cmdline-tools/latest/bin/sdkmanager --licenses
/opt/android-sdk/cmdline-tools/latest/bin/sdkmanager "platform-tools" "platforms;android-34" "build-tools;34.0.0"
```

**第 3 步：放回签名密钥**

```bash
mkdir -p ~/.android
cp /workspace/debug.keystore ~/.android/debug.keystore
keytool -list -keystore ~/.android/debug.keystore -storepass '<storePassword>' -alias '<keyAlias>'
```

指纹必须是：

```
EC:6B:79:F8:BA:D7:51:38:96:4A:1B:3F:77:EF:89:06:B2:5C:66:97:E7:9C:4D:0A:E8:3F:73:14:C1:6A:77:12
```

对不上就说明拿错了文件，装出来的包会报「签名不一致」，只能卸载重装、设置全丢。

> 公开仓库注意事项：**keystore 文件本身不在仓库里**（`.gitignore` 已排除 `*.keystore` / `*.jks`），
> `app/build.gradle` 改为「本机有这个文件才用它签」，别人 clone 下来会得到未签名的 release 包，
> debug 包退回 AGP 默认签名，能装能测。想自己签，在 `signingConfigs` 里加一个指向你自己
> keystore 的 `release` 配置即可——密码与别名按你自己的填，别照抄本文的占位符。

**第 4 步：验证能构建**

```bash
cd /workspace/DaxiaoWeekAlarm && ./gradlew testDebugUnitTest --console=plain 2>&1 | tail -20
```

**期望 0 失败**（条数以 `交接-给下一个会话.md` 第 1 节为准——每发一版都会变，写死必然过期）。
这一条同时验证：JDK 通了、SDK 通了、依赖拉全了、代码完整。
首次构建要下载 Gradle 8.7 与依赖，5–15 分钟，**用 `run_in_background` 等，别用短超时**。
仓库已配好国内镜像：Gradle 走 `mirrors.cloud.tencent.com`，Maven 走 `mirrors.tencent.com`。

**沙箱坑：`~/.gradle/init.gradle`**。预置内容可能是坏的（`url https://...` 缺 `=` 和引号、
`mavelCentral()` 拼错），改好还会撞上项目的 `FAIL_ON_PROJECT_REPOS`——不能在 `allprojects{}` 里声明仓库，
只能在 settings 层注入：

```groovy
settingsEvaluated { settings ->
    def repos = settings.dependencyResolutionManagement.repositories
    repos.maven { url "https://mirrors.tencent.com/nexus/repository/maven-public/" }
    repos.google()
    repos.mavenCentral()
    def pluginRepos = settings.pluginManagement.repositories
    pluginRepos.maven { url "https://mirrors.tencent.com/nexus/repository/maven-public/" }
    pluginRepos.google()
    pluginRepos.mavenCentral()
    pluginRepos.gradlePluginPortal()
}
```

## 三、签名（唯一「丢了不可挽回」的东西）

| 项 | 值 |
| --- | --- |
| 文件 | `/workspace/debug.keystore`（**不在仓库里**，`.gitignore` 已排除，自行保管） |
| 别名 | `androiddebugkey` |
| 密码 / storePassword | Android 调试密钥的通用默认值，本文不落明文；按你手里的文件填 |
| 指纹（SHA256） | `EC:6B:79:F8:BA:D7:51:38:96:4A:1B:3F:77:EF:89:06:B2:5C:66:97:E7:9C:4D:0A:E8:3F:73:14:C1:6A:77:12` |
| 生成时间 | 2026-10-20（本项目沙箱首次构建时由构建工具自动生成） |

**它不是老 ADT 时代那个“人人相同、固定指纹”的公共 debug.keystore**——别名、密码、证书主体
（`CN=Android Debug`）是标准三件套，但密钥对是本机独有的：随机序列号、30 年有效期
（到 2056-10-12）、PKCS12 格式。每台机器自动生成的都不一样，所以：

- **它只在这一台机器 / 这一个沙箱里有效**。沙箱重建或文件丢失 → 必须用 `/workspace/debug.keystore`
  备份恢复（`md5sum` 应对上 `127b140f0c3a2180968e9968e31de1ed`）。恢复不了，新签的包装不到旧包上方，
  报「签名不一致」，只能卸载重装、设置全丢。
- 用户手机上已装的包是它签的：**只要还在这个沙箱出包，覆盖安装一直没问题**。
- **测试期与 GitHub 直接分发够用**（GitHub 用户各自动生成自己的 debug 密钥，互不覆盖，不妨碍）。
- 只有将来上应用商店才必须换正式密钥（换后老用户无法覆盖安装，只能卸载重装、设置全丢，
  只能换包名重新上架）——届时请让用户自己另存到手机 / 网盘，并重新生成灾备包。

## 五、这套东西是怎么来的（给新会话的背景）

- 项目名：打工人闹钟（原名「大小周闹钟」，v1.22.0 改名），Android 原生 Java，无第三方依赖
- 包名：`com.daxz.weekalarm`
- 唯一用户就是开发者本人，当前处于测试期，版本号可以随便排、设置丢了也不心疼
- 开发节奏极快：10/20 从零开始，三天做到 v1.46.6
- 用户偏好：不喜欢冗余功能（年度闹钟做过又撤、闹钟总开关删了、日历折叠直接否）、要求布局紧凑、反感「差不多就行」

用户几次判断的原话，值得记住：

> 「闹钟总开关似乎没有什么必要，然后闹钟放在日历下边有点怪怪的」
> 「我觉得日历折叠这个功能没有必要」

都成立，说明用户的界面直觉很准。**布局改动前先出线框给他看**，能省掉大量往返。
