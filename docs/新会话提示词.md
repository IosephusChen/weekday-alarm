# 新会话提示词（沙箱重置后开工用）

> 为什么有这份文件：Trae 的沙箱是临时的——容器重启会把 `/root`、`/opt` 恢复成镜像初始状态，
> 平台还会把工作区切到它自己的快照分支 `trae/agent-*`（2026-11-13 实测两次）。
> 只有推到 GitHub 的东西活下来。所以每开一个新会话，把下面整段粘进去。

---

```text
接手 /workspace 下的 Android 项目「打工人闹钟」（GitHub: IosephusChen/weekday-alarm）。
这是沙箱重置后的会话：/root 与 /opt 可能被清空，/workspace 可能保留。请按顺序做，别跳步。

【第一步：拉代码 + 装环境】
# 2026-11-14 实测：重置只清 /root 与 /opt，/workspace 里的仓库还在。
# 目录已存在就别再 clone，否则直接报 already exists。
if [ -d /workspace/weekday-alarm/.git ]; then
  cd /workspace/weekday-alarm && git checkout main && git pull --rebase
else
  cd /workspace && git clone https://gh-proxy.com/https://github.com/IosephusChen/weekday-alarm.git
  cd weekday-alarm && git checkout main
fi
bash tools/setup-env.sh
（直连 github.com 会卡死，只用 gh-proxy 前缀。setup-env.sh 只补缺的：JDK、git 身份、
 local.properties、Android SDK，补环境约 20 秒（2026-11-14 实测 17 秒）；首次跑单测要下
 依赖，6–10 分钟，和补环境在同一条命令里，别中途杀进程。）

【第二步：凭据】
setup-env.sh 可能自动落盘 NAS 凭据；没有 /root/.nas_credentials 就执行（真实值向用户要，
不要写进仓库）：
bash tools/set-access.sh --base="<NAS_BASE>" --user=<USER> --pass='<PASS>'
base 必须带 %20 / UTF-8 百分号编码，且写到 …/weekday-alarm 这一级，否则探活 404。
推送 token：bash tools/nas.sh get keys/github-token.txt /root/.github_token && chmod 600 /root/.github_token
（2026-11-14 实测 gh 登录态不一定保留，gh auth token 为空时别反复重试，直接走 NAS。）
签名材料：bash tools/fetch-keys.sh（只在出包时需要）。

【第三步：看状态，别先动手】
bash tools/handoff.sh
再按顺序读：AGENTS.md（纪律）→ PLAN.md 开头的「交接条」→ docs/项目状态.md。
现状、测试条数、待办以 handoff.sh 输出和交接条为准，别抄提示词里的快照数字。

【重要：这个平台会把工作区切到它自己的快照分支】
如果 `git log -1 --format=%s` 是 "feat: update workspace"，或分支是 trae/agent-*，
那是在旧快照上，立刻 git checkout main（handoff.sh 现在会直接把这条排在「下一步」第一条）。
任何改动做完立刻 commit 并 bash tools/push.sh，不要长时间把工作留在未提交状态
（沙箱可能被重置，只有推到 GitHub 的东西才活下来）。

【待办只有这些，别自己找活】
1. 真机验收（等用户回复，别替他判断）：v1.27.1 设置页关机闹钟那行有开关；关掉后关机不响；
   响铃卡末尾说明在小屏是否压得住；站内更新能否拉起安装器。
2. README 截图 3 张（首页上班日 / 设置 / 本月小组件），等用户给图，压到 235 宽并更新 alt。
3. 其余历史验收项在 docs/验机清单.md，用户说「最后统一处理」，不要催。
（这三条与 PLAN.md 交接条的「下一步」重复，以那里为准；对不上说明这份提示词过期了。）

【纪律摘要（详见 AGENTS.md）】
- 不写方案不出包：release.sh 要求 PLAN.md 有 "> 状态：**已批准**" 且 "> 目标版本：" 只含一个数字。
- 版本号只在 release 提交里动；release.sh 全量测试 + lint 通过才算完。
- 看不到屏幕就别改 UI / 文案观感；不确定的先问，不要猜。
- 一处改动配一处反向验证（先让测试在旧代码上红）。
```

## 2026-11-13 两次重置的现场记录

| 现象 | 证据 | 处理 |
|---|---|---|
| 容器重启，SDK / Gradle 缓存 / NAS 凭据全没了 | `/proc/uptime` 只有 64 分钟；`supervisord.log` 首行 `started with pid 837` | 重跑 `tools/setup-env.sh` |
| 文件看起来「被删除」、代码回到旧版本 | `git reflog`：提交后 15 秒出现 `checkout: moving from main to trae/agent-YjQQ4g`，该分支 HEAD 是 `feat: update workspace`（旧快照） | `git checkout main`，代码没丢 |
| 401 / 无法取 keystore | `/root/.nas_url`、`/root/.nas_credentials` 随 `/root` 一起被清 | `tools/set-access.sh --base=… --user=… --pass=…`（base 写到 `…/weekday-alarm`） |
| 2026-11-14：只清 `/root` 与 `/opt`，`/workspace` 保留 | 仓库、`local.properties`、git 身份都在；SDK / Gradle 缓存 / NAS 凭据 / GitHub token 全没 | 跳过 clone，`checkout main` 后 `setup-env.sh --no-test` 补回 SDK（17 秒），再补凭据 |
