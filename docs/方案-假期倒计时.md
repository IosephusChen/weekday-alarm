# 方案 · 假期倒计时（P3，v1.68.0，已实现）

> 用户 2026-10-25 拍板：**只做「距下一个法定假期还有 N 天」，不做全节日罗列**
> （与日历已有的节日标记重复）。数据用现成的节假日层，不新增权限、不新增网络请求。
>
> **落地记录（2026-10-25）**：`HolidayCountdown` 纯函数 + 首页今天状态卡新增
> `tv_holiday_countdown` 一行；12 条测试（`HolidayCountdownTest` 10 + 
> `MainActivityHolidayCountdownTest` 2）。与原方案的两处偏差：① 块内**第一天**
> 显示「今天国庆」（原表现「第 1 天」，第一页就说不通）；② 假期里取不到名字时
> 退化为「假期第 k 天」（原方案只写了假期外的退化）。

## 1. 目标与非目标

| | 内容 |
| --- | --- |
| 目标 | 首页「今天状态卡」里多一行：普通日子显示「距元旦还有 23 天」，假期里显示假期进度 |
| 非目标 | 不做节日列表、不进小部件（v1.62.0 刚定稿「桌面只留一眼决策」，不再往上堆）、不新增设置开关、不做点击跳转 |

## 2. 数据源与边界

复用 `HolidayData`（内置 2007–2026 + 在线增量）：

- `isHoliday(d)`：这天放不放假（远程优先，补班日恒为 false）
- `holidayName(d)`：节日简称（2 字）；**远程逐日名不可靠**（holiday-cn 会把九天都写成「春节」），
  名字统一取**假日块第一天**的内置名，取不到才退远程名
- **数据边界**：向前扫描窗口 **120 天**（正常年份最长假期间隔约 60–70 天，120 天足够）；
  窗口内一个假日都没有 → 视为「看不到那么远」，**这一行不显示**（不猜、不显示错的数字）

## 3. 文案规则（纯函数 `HolidayCountdown.compute(today)` 的输出）

| 场景 | 文案 | 例 |
| --- | --- | --- |
| 普通日，前方有假期 | `距{节日}还有 {N} 天` | 距元旦还有 23 天 |
| 明天就是假期第一天 | `明天就是{节日}` | 明天就是元旦 |
| 今天是假期第一天 | `今天{节日}` | 今天元旦 |
| 假期进行中（第 k 天） | `{节日}假期第 {k} 天` | 春节假期第 2 天 |
| 假期最后一天 | `{节日}今天结束` | 国庆今天结束 |
| 名字取不到（内置 + 远程都没有） | 退化：`距下次放假还有 {N} 天`（不带节日名） | 距下次放假还有 40 天 |
| 120 天窗口内无假日数据 | **不显示这一行** | — |

跨年假日的连续块（如元旦 + 周末相连）按 `isHoliday` 的连续段整体算「一个块」，
块名取第一天；块内任意天都用同一个块名。

## 4. 位置（首页今天状态卡内新增一行）

- 卡片结构不动：还是「今天什么情况 → 闹钟 → 日历」三张卡、顺序不变（用户红线）
- 新增行放在 `tv_today_sub`（副信息，说的是闹钟）**下方** 2dp，12sp / sub 色，
  与副信息视觉从属——副信息管闹钟，新行管假期，两件事不混在一行
- 请假 / 加班 / 全部闹钟关闭等场景：该行照常显示（假期倒计时与今天上不上班无关）
- 线框：`docs/预览-假期倒计时.html`

## 5. 实现要点

1. **新增 `HolidayCountdown`**：一个纯函数 + 一个 Model 类（同 `MonthWidgetRender.compute`
   的路子——JVM 可测、不碰 Android framework）。扫描逻辑只调 `HolidayData` 三个查询方法。
2. **跨天刷新**：首页 `refreshAll()` 已按天重算（`tickDay`），把新行并进去即可；
   无需新的刷新通道。
3. **小组件不动**：`NextAlarmWidget` 的副信息保持「日期 · 闹钟名」（v1.62.0 定稿）。

## 7. 验收

用户真机：连放几天假的日子逐天看文案是否对（尤其假期中与最后一天）；
跨年那几天（12/30–1/2）重点看块合并是否正确。
