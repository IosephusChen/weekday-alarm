# 小米超级岛 · 提报材料（初稿）

> 状态：**初稿，未提报**。写于 2026-10-25，依据小米澎湃OS开发者平台官方文档
> （接入流程，更新时间 2025-12-05）整理。用途：将来若决定上小米应用商店，按这份材料启动。
> 当前方向是 GitHub 开源优先、商店暂缓——本材料是**触发式待办**，不是现在要做的事。

## 〇、先说结论（三条）

1. **商店上架是超级岛的前置**。官方接入流程原文：开通服务时「进入手机/平板应用选择您需要
   开通小米超级岛的**在架应用**」——即要先在小米开放平台完成应用创建、资料审核、
   包体上传并通过应用审核（1-3 个工作日）。这与已确认的「上商店 = 软著 + ICP 备案 +
   APP 备案 + 隐私合规」资质线是同一件事的两面。
2. **闹钟类场景大概率是超级岛可接受的场景**。超级岛面向「重要通知、应用服务、设备状态」三类，
   闹钟响铃属于典型焦点通知；官方文档明确会驳回的是「运营活动、促销、借款」类内容，
   工具类不踩线。闹钟类无公开禁令，但预审结果以小米审核为准——这正是「先提报问清楚」的意义。
3. **实现方式选客户端实现，不开 MIpush**。打工人闹钟是本地闹钟，响铃时本就有前台服务
   在跑，客户端实现（按原生通知扩展发岛通知）即可；MIpush 是给「客户端不在场也要
   推送上岛」的场景用的，我们不需要。

## 一、官方准入流程（六步，2025-12-05 版文档）

| 步 | 事项 | 周期/要点 |
| --- | --- | --- |
| 1 | 注册小米账号 → **开发者认证**（个人/企业，提交认证材料，人工审核） | 1-3 个工作日；驳回需改后重提 |
| 2 | **创建应用** + 完善资料 + 上传包体 → 应用审核 | 1-3 个工作日；海外开平与国内相互独立 |
| 3 | 开通服务：客户端实现直接开「小米超级岛」服务；云侧推送需先开通推送服务 | 填联系信息 + 配置指纹证书 |
| 4 | **场景和方案提报**（两步）：① 上岛场景预审（文案描述业务场景与核心信息）→ ② 正式方案审核（完整方案：通知开始到结束的**所有变化节点** + 每节点的信息与**效果图**，官方有提报模板） | 运营/促销/借款类场景会被驳回 |
| 5 | 联调测试：设备白名单管理（按 OAID 添加，**每应用上限 10 台、有效期 30 天**）；配置 `com.xiaomi.xms.APP_ID` 与 `com.xiaomi.xms.BUILD_TYPE_DEBUG` 两个 meta-data | Debug 包需配测试证书指纹 |
| 6 | 上线验证：提交**正式环境 APK** + 场景验证方法 → 通过获正式权限 → 发版 | 初次上线**灰度 7-15 天**全量 |

> 红线：新增场景必须重走「预审→正式审核→上线验证」；未经审核的场景上线会导致
> 超级岛服务被停用，严重的可能下架。

## 二、我方上岛场景方案（提报正文用）

**应用**：打工人闹钟（包名 `com.daxz.weekalarm`）
**场景一句话**：闹钟响铃及响铃全过程的焦点通知展示（预审文案就用这句，别加形容词）。

**节点表**（正式方案审核的核心材料，每个节点都要文案 + 效果图）：

| 节点 | 触发 | 岛展示内容 | 用户操作 |
| --- | --- | --- | --- |
| ① 即将响铃 | 到达响铃时间前 N 分钟（可配置，默认同现有提前提醒逻辑） | 「XX 闹钟即将响铃」+ 时间 | 点击进响铃页 / 忽略 |
| ② 响铃中 | AlarmService 响铃 | 闹钟时间 + 标签（如「起床」）+ 响铃状态 | 停止 / 小睡 |
| ③ 小睡中 | 用户点小睡 | 「小睡中，XX:XX 再响」+ 倒计时 | 点进响铃页 / 立即停止 |
| ④ 已停止 | 用户停止或自动解除 | 结束态短时展示后收起 | 无 |

**效果图要求**：按节点各出一张（现在可以先不画，提报前照 `docs/预览-*.html` 的
线框风格补四张即可）。

## 三、技术对接要点（提报通过后再看）

- manifest 加两个 meta-data：`com.xiaomi.xms.APP_ID`（开通服务时生成）与
  `com.xiaomi.xms.BUILD_TYPE_DEBUG`（debug 包 true、release false）；
  平台同时配正式证书指纹与测试证书指纹。
- 客户端实现 = 按原生通知方式发岛通知（Notification 扩展字段），响铃页/服务的通知
  逻辑已具备，改造点预计集中在通知构建与节点回调。
- OS2 焦点通知与 OS3 超级岛都接的话，代码要合并进同一个 APK 统一验证
  （OS2 还需发邮件到 mipush-permission@xiaomi.com 申请开发测试包）。

## 四、时间线预估（决定上商店时）

开发者认证 + 应用审核约 1 周；方案提报两轮审核约 1-2 周；联调与上线验证约 1 周；
灰度 7-15 天。合计**约 1.5-2 个月**，与商店资质线（软著 1-2 个月、备案 20 工作日左右）
并行推进。这些都是公开文档与公开经验值，实际以审核为准。
