版本 v0.82.1 · 说明随版本更新

引导页：每一项为什么留、为什么走

现元素方案理由
「上一步」在顶栏、「下一步」在底栏两个方向键都收到页脚同一件事的两个方向分居屏幕两角，翻页时眼睛要跑两趟；手指也够不到顶栏左角
「导入」与「跳过」并列在顶栏「跳过」留顶栏，「导入配置」降到第 1 页正文末尾一个是「我有旧配置」，一个是「我不想设」，并列成两个小字按钮，读起来像同一类出口
圆点在页脚，和主按钮抢位置圆点移到页面上方页脚只放两个动作；进度指示属于「你在第几步」，不是动作
第 2 页：时间 + 音量 + 渐响 + 稍后 + 前提醒（5 个决定）只留时间，其余压成一行只读摘要引导的目标是「能响、响得对」；四响铃项一次设好基本不动，1% 的人要改，不该让 99% 先做选择
第 3 页：5 项权限平铺拆两档：能检测的 3 项 / 读不到状态的 2 项（带一句解释）五项长得一样，但打完勾的结果不一样——上面三项会变绿，下面两项永远不会，平铺会让人以为「还有两项没成功」
两个测试是大卡片，紧挨「开始使用」降为两行次级链接测试是「验一下」，不是「下一步」；现在是两个大卡片和一个主按钮抢同一个视觉层级

说明页：从「一篇文章」改成「五张卡」

现状方案为什么
16 段、约 1250 字，无目录顶部 5 枚目录胶囊 + 5 张分节卡，每节 3 条以内用户是带着问题来的（「组件怎么加」），要么扫到，要么滚到底——现在是后者
段落 80–110 字，一句话里塞三件事一条一句话，最多 25 字手机上 110 字是一整屏灰字；拆成条才能一眼扫
「入口在设置 → 更多设置 → 使用说明」写成死文字做成可点的行，直接跳对应页说明页和设置页本来就该互通；路径文字改版就会过期（这版已经有一处过期，见下）
文案硬编码在 393 行布局里每节一条 string，布局只搭壳改一句话要动 XML、还要重排 padding；v0.82 改完组名，这页就漏改了一处

已经过期的例子：说明页 ⑤ 里写着「响铃时长、渐响、震动、稍后提醒、按键在『更多响铃设置』」， v0.82.0 已把稍后提醒搬回主页「提醒」组。这正是「文案写死 + 无守门测试」的结果。

代价与风险（动手前说清）

① 这是两个主题，得拆两版还是合一版？建议合一版（0.83.0）：两页都是「新手第一次看到的东西」， 同一次改完才能对着真机一起验收；拆两版反而要发两次包。

② 引导页会动测试。GuideTest 按 R.id.* 断言页面内容和选中态， 删掉第 2 页那四行、把「导入」挪位置，都会让它红。预计改 6–8 条断言，不是重写。

③ 说明页改成「文案进 strings」要多一步。HelpActivityTest 现在是按界面元素找文案， 改成读 string 后断言要跟着换口径；好处是以后改文案不用碰布局。

④ 第 3 页可能还是长。5 行权限 + 2 行测试 + 3 个标题，比我删掉的第 2 页还是多。 真机上如果仍要滚，可考虑把「试听 / 测锁屏」挪到「开始使用」之后的一次性提示里——但那要多一个弹窗，先不做。

我的建议：按图上做，0.83.0 一版发完。这两页是「新用户看到的第一屏」和「遇到问题的第一站」， 现在一个是九次决定、一个是 1250 字长文，都跟 App 现在的克制风格不搭。
