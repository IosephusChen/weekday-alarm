落地要点

项做法
布局重写 dialog_calendar_content.xml：三张卡用同一个 item 结构，选中态用 state_selected 驱动背景 / 描边 / 勾的显隐（selector，不在代码里逐个 setBackground）
交互整卡点击切换，不依赖 CheckBox 自身热区；保留 contentDescription 供无障碍读出「已选 / 未选」
代码showCalendarContentDialog() 里 cb_* 三个字段换成卡片的点击切换 + 确定时读三个布尔写 Prefs；三个 Prefs 键不动，备份格式不变
不动文案一字不改（标题 / 说明 / 三项名称），弹窗尺寸仍由内容撑开，「完成」仍是显式确认
测试守门：三项默认值 round-trip（开 / 开 / 关 → 改 → 落盘）、点击切换后确定写入、取消不写

为什么不顺手改成「点一下就生效、去掉完成按钮」：这是唯一的多选弹窗，误触成本比单选高， 保留显式确认；若 A11 整体定稿时认为应统一成即时生效，单独再议。
