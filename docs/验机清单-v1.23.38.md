## 装包

从 [Releases v1.23.38](https://github.com/IosephusChen/weekday-alarm/releases) 下 APK 直接覆盖安装。
签名一致，数据保留，不需要先卸载。

**别装 debug 包**：它与正式版同包名，装之前要先卸载正式版，班表与请假记录会全部丢失；
而且 `App.java` 里两处 `if (!BuildConfig.DEBUG)` 让 debug 包不拉节假日、不查更新，
「debug 缺的那半截」很容易被误判成新代码的 bug。

## 第一组：响铃链路（1–4，一轮做完）

先建一条「1 分钟后响」的闹钟，或直接进 设置 → 帮助 里的「测试响铃」。

1. **测试响铃能结束** —— 进测试响铃，铃声起来后点「停止」。预期：声音立刻停、通知撤下，
   再进一次还能正常响（不残留状态）。
2. **通知「停止」立即停** —— 闹钟响时下拉通知，点「停止」。预期：一键静音，
   不需要点进响铃页。**不过的典型现象**：点了没反应，或要连点两次。
3. **「N 分钟后再响」** —— 再响一次，点「5 分钟后再响」。预期：立即静音，
   5 分钟后再响；再响时仍然可以停止。**注意**：跨零点的小睡（23:5x 点小睡）属第 7 条一类的场景。
4. **首页那行与悬浮横幅** —— 解锁使用时响铃，会出现悬浮横幅与首页顶部的响铃状态行。
   两个位置的「停止」和「小睡」各点一次。预期：行为与通知上的按钮一致。

## 第二组：数据（5）

5. **导出再导入** —— 设置 → 导出配置存一份 → 再导入同一份。预期：
   - 轮班定义的**班次名**还在（白班 / 夜班）；
   - **N 天轮值**还在（不是退回默认）；
   - 挂在班次上的闹钟时间没退回自己的 `hh:mm`。

   见过的问题就在这三处：备份曾经只存闹钟不存班次表，导入后「跟班次的闹钟」全部掉回自己的时间。

## 第三组：跨天（6、7，要过夜）

6. **「这次不响」不复活** —— 对首页「下次闹钟」点「这次不响」，等到那个点确认确实没响；
   第二天再看，这条闹钟应正常排下一个。**不过的典型现象**：第二天那条取消标记自己消失了，
   或者反而在别的日子不响。
7. **跨零点夜班** —— 建一个夜班（20:00–次日 08:00）的轮班，闹钟挂在夜班上、
   偏移设「结束前 30 分」，它排出的响铃是**次日 07:30**。分两次看：
   - 今晚 0 点以后打开 App → 首页「下次闹钟」**仍显示明天 07:30**（被抹掉就是没过）；
   - 明早 07:30 → 确认真的响。

   这条对应的是「逻辑日」与「响铃日」拆开的那次重构：实例身份改按响铃日，
   而班表判定仍按逻辑日。修复前，次日零点那次例行重排会把夜里生成的实例当成过期抹掉。

## 回报格式

每条一句：「过 / 不过 + 现象」。不过时补三样：

1. 手机型号与系统版本（设置 → 关于手机）；
2. 这条闹钟当时怎么设的（设置页截图最快）；
3. 现象截图或录屏。

研发侧拿到「不过」的第一件事是补一条**在修复前会红**的测试，所以现象描述越具体越好——
「没响」和「响了但通知上没有停止按钮」是两条完全不同的路径。
